# TMNT — события

React + Vite. Карточки, страницы событий и метаданные собираются из одного каталога.
Существующие адреса `/events/drum+nuwei/`, `/events/temnota-1/`, `/events/temnota-2/`,
`/events/vinyl-practice/`, `/events/dram-360/` и `/privacy-policy/` сохранены.

## Разработка

Нужен Node.js 24 (версия указана в `.nvmrc`).

```sh
npm ci
npm run dev
```

## Добавление или изменение события

Редактируйте `src/data/events.js`:

- `slug` — адрес страницы; не меняйте его у опубликованного события без редиректа.
- `title`, `dateLabel`, `venue`, `cover`, `description` — общие данные для страницы и карточки.
- `status`: `upcoming` или `past`; `listed: true` показывает событие в соответствующем списке.
- `layout: 'detail'` — афиша и описание; `blocks` содержит абзацы, цитаты, билеты и направления.
- `layout: 'gallery'` — фоторепортаж; `photos` и `credit` задают фотографии и автора.
- `map` и `socialGroup` включают карту и ссылки DRAM.
- `index` — номер на карточке. Порядок карточек совпадает с порядком в каталоге.

Положите изображения в `public/` и укажите путь вида `/poster.webp`.
Новая запись автоматически создаёт страницу и её метаданные при сборке.
Статус выставляется явно: дата в афише может отличаться от текста, поэтому приложение
не пытается определить её из изображения или строки. У DRAM 360 сохранено 12 декабря
без придуманного года, на присланной афише стоит 12/09. Билеты DRAM 360 открываются через Radario: блок `ticketWidget`, `eventId: 2877223`.
Цвета виджета задаются в `params` этого блока.

Общие шапка, подвал, карточки, описание, карта и галерея находятся в `src/components/`.
Настройки домена и сайта — `src/data/site.js`. Текст политики — `src/pages/PrivacyPage.jsx`.
Существующее оформление сохранено в `src/styles.css`; стили прежнего скрытого лендинга
пока сохранены, чтобы отделить миграцию компонентов от визуального редизайна.

## Карта

`LocationMap` использует встраиваемую карту Яндекса без API-ключа. Координаты
и подпись берутся из `map` в каталоге событий. Метка показывает клуб, рядом
есть адрес и ссылка на полноэкранную карту. Тёмное оформление iframe сделано
CSS-фильтром; это визуальная адаптация светлой подложки, а не нативная тема API.

## Сборка и проверка

```sh
npm run build
npm test
npm run preview
```

Сборка создаёт клиентское React-приложение и генерирует HTML для каждого адреса
из тех же компонентов. React подключает интерактивность к готовой разметке.
Это сохраняет содержимое и превью Telegram без необходимости исполнять JavaScript
поисковым роботом. `.render/` — временная серверная сборка, `dist/` — результат публикации.
Обычные ссылки между страницами обеспечивают прямые переходы и работу браузерной истории.

## Cloudflare Workers Static Assets

Конфигурация находится в `wrangler.jsonc`. Сервер постоянно держать включённым не нужно.
Текущему сайту не нужна база данных: все события хранятся в каталоге проекта.
Workers API и D1 можно подключить при появлении админки, регистрации или бронирований.

Для первой публикации в выбранный аккаунт:

```sh
npx wrangler login
npm run deploy
```

Сначала проверьте выданный адрес `workers.dev`, все страницы, галереи и карту.
Затем подключите `tmntptz.ru` как Custom Domain в Cloudflare. Перенос DNS/домена
не выполнен этим рефакторингом. До переключения сохраните текущий GitHub Pages для отката.
Для автоматической сборки подключите репозиторий в Workers Builds:
команда сборки `npm run build`, команда публикации `npx wrangler deploy`, Node.js 24.

Документация: https://developers.cloudflare.com/workers/static-assets/get-started/

## Если оставить GitHub Pages

React не требует смены хостинга. Публиковать нужно **содержимое `dist/`** через
GitHub Actions, а не исходники корня репозитория. `CNAME` и `.nojekyll` переносятся
в результат сборки. Для GitHub Pages, работающего на `tmntptz.ru`, пути уже настроены.
Подпапка вида `username.github.io/repository/` потребует отдельной настройки базового пути.
